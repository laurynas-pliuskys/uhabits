  <project_name>Loop Routine Manager (Evolution of Loop Habit Tracker)</project_name>

  <overview>
    This project transforms the existing Loop Habit Tracker into a hierarchical Routine Manager with advanced interval gap analysis capabilities. The current Loop Habit Tracker is an open-source Android application (GPLv3) that helps users create and maintain good habits through tracking, detailed statistics, and visualizations. The evolution to Routine Manager introduces: (1) Hierarchical Data Structure - enabling parent-child relationships between habits, allowing top-level &quot;Routines&quot; to contain sub-habits &quot;Items&quot;; (2) Expandable Accordion UI - transforming the flat RecyclerView list into grouped, expandable sections while maintaining the 7-day completion grid; (3) Trinary State Logic - extending the checkmark system from binary (Yes/No) to three states: Success (Tick), Failure (Cross), and Unknown (Grey Circle); (4) Interval Analysis Engine - calculating gaps between specific states (e.g., days between failures); (5) Gap Visualization - new statistics view with bar charts showing stint durations and Simple Moving Average (SMA) trend lines. The project maintains backward compatibility with existing Loop data and adheres to Material Design 3 patterns.
  </overview>

    <feature>
      <name>Add Parent-Child Relationship Schema</name>
      <description>Create database migration (26.sql) with two new tables instead of modifying the habits table. A routine is NOT a habit - it is a named container with no entries, scores, or streaks of its own. Schema: (1) &apos;routines&apos; table with id, name, color, position columns to store routine display properties; (2) &apos;routine_items&apos; table with routine_id (FK to routines), habit_id (FK to habits, UNIQUE), position columns to map habits into routines. Includes indexes on routine_items(routine_id) and routine_items(habit_id). This approach leaves the existing habits table completely untouched for backward compatibility.</description>
